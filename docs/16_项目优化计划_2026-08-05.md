## 一、现状定位

项目已从 V1（"检索完让 LLM 编 idea"，幻觉严重、idea 全 reject）成功重构为 V2（Evidence-grounded：Contract → Questions → 多轮检索 → Evidence 抽取 → Coverage → Gap Mining → Gap Audit → Intervention → Minimal Experiment → Idea）。V2 方向正确——用证据驱动 + 对抗审计对抗 LLM 幻觉是正解。

但当前代码经核对存在一个结构性矛盾：**V2 是一条串行长链，链上有 7 道硬闸门，任何一道不通过任务就以 `more_research_required` / `abstained` / `insufficient_evidence` 直接终止。** 假设每道闸门通过率乐观地取 0.7，端到端通过率约0.7^7 ≈ 8%。这不是某个 bug，而是"全严硬闸门串联 + 上游供给不足 + 无降级回环"的结构性问题。

docs/15（2026-08-03）已落地五项缓解（O3放松 readiness 一票否决、O4 S2 限速自适应、O5b Gap 层 A/B 分档、O6 limitation 抽取增强、O9 领域态势简报），最新 commit 又新增了 gap 挖掘/检索两道形式化准入门（`evidence-admission-v1`、`gap-search-admission-v1`）。但经代码核对，以下关键优化**仍未落地**，正是本计划的重点。

---

## 二、当前仍未闭合的关键差距（代码级证据）

第一，定向补检索回环完全缺失。`runner.py` 的 6 个失败出口（readiness、no_gap、no_surviving_gap、no_intervention、abstained、insufficient_evidence）全部是"生成简报 → 更新状态 → 直接 return"，没有"读取失败原因 → 生成针对性补充query → 回到失败闸门重试"的回环。这意味着任何一环卡住，任务立即终止，用户只能拿到一份简报。

第二，S2 API key 为空导致限速自适应形同虚设。`config.py` 的 `effective_s2_rate_per_min` 逻辑正确（有 key 时 5000/min），但 `.env` 与 `.env.example` 中 `SEMANTIC_SCHOLAR_API_KEY=` 为空，实际仍走 20/min 保守限速。S2 是唯一带venue + citation + 引用关系的高质量源，限流后经典论文缺失，Gap 审计的近邻对比失去参照，审计恒返回 uncertain，Gap 拿不到 surviving。

第三，全文 RAG 在 Windows 上仍禁用，且供给与需求错配。`runner.py:489` 硬编码跳过 RAG，`rag_service.py:974` 的 `rag_retrieve` 直接 `return []`，embedding 仍绑定本地 sentence_transformers/bge（Windows PyTorch segfault）。而 Gap 挖掘/审计的准入门偏好"全文可定位证据"——供给只有abstract，需求要full-text，结构性错配。未引入 OpenAI/Venus 的 API embedding 替代。

第四，检索无预过滤，噪声入库。`search_papers.py` 对检索结果逐条 upsert 全部入库，无 embedding/相似度预筛。6 源 × 5 query × 15篇 ≈ 450篇/轮，大量与主题无关的噪声（历史实测出现过肝癌分类、人脸识别混入 test oracle 主题），拉低 evidence 抽取和 Gap 挖掘的信噪比。

第五，分级产出只落到 Gap 层，Intervention 与 Idea 仍是硬闸门。Gap 有 provenance_status（complete/partial，即 A/B 档），但 Intervention 是 PASS/FAIL/UNKNOWN，Idea 是 go/revise/reject 硬阈值，无 confidence_tier 贯通。用户无法拿到"标清置信度的分级方向让我挑"。

第六，前端未适配 V2。前端仍是旧的 报告/论文/知识库/创意/实验/轨迹 六页签，无 Gap / Intervention / Landscape Brief / confidence_tier 的专用展示。V2 最有价值的中间产物（研究问题树、覆盖矩阵、Gap 及审计状态、诚实的"为何没产出"解释）用户看不到，或只能挤在旧 Report 通道里。

第七，评分无跨论文校准。`score_papers.py` 每篇论文独立并发调LLM 打分，无归一化/排名重标定，历史实测高优先级论文分差仅 0.047，区分度极低。

第八，工程卫生问题。`backend/` 根目录堆积了约 20 个 `server*.log` / `*.err` / `stdout.log` 等运行日志文件，混在源码目录且已入版本库视野；`deep_research.db` 及 WAL 文件也在其中。这类文件应纳入 `.gitignore` 并清理。

## 三、优化计划（按投入产出比分档）

### 第0 档：立即可做（10 分钟，收益最大）

配置 Semantic Scholar API Key。免费申请（https://www.semanticscholar.org/product/api#api-key-form），填入 `.env` 的 `SEMANTIC_SCHOLAR_API_KEY`。`config.py` 已有自适应逻辑，填key 后限速自动从 20/min 提到 5000/min，429 基本消失，经典论文与引用关系回归，Gap 审计的近邻对比立刻有料。这是解锁后续所有闸门通过率的前置条件，不做这一步，第二、三档的收益都会被限流吃掉。

同步清理工程卫生：把 `backend/server*.log`、`*.err`、`stdout.log`、`stderr.log`、`deep_research.db*`、`pdf_cache/`、`paper_assets/` 加入 `.gitignore`，删除已堆积的运行日志。

### 第1 档：让链路"能出东西"（3-5 天，结构性，最高优先）

这一档不放宽闸门的严格性（避免退回 V1 让 LLM 乱编），而是改链路形态，把"卡住即终止"变成"降级 + 定向补检索回环"。

O2 定向补检索回环（核心）。在 runner.py 的每个 `more_research_required` 出口，不再直接 return，而是：读取失败的 reason_code（缺 limitation / 缺近邻 / 缺 gap 专属论文 / 覆盖不足）→ 针对性生成补充 query（缺 limitation → 检索 "limitations of X" / "failure cases of X"；缺近邻 → 检索 Gap 的 claimed_delta 相关工作）→ 跑 1 轮定向检索 → 回到失败的那个闸门重试，设最多 N 次（建议 2次）与总预算上限。runner 已有 `_idea_retry_search_round` 雏形可复用，但需接到 V2 链路的失败出口上，并带 reason 驱动。

O1 分级产出贯通到 Intervention 与 Idea。把 Gap 层已有的 A/B 档思路延伸：Intervention 硬闸门不通过时不丢弃，降级为 B/C 档入库并标注"证据部分支撑/推测性，需人工判断"；Idea 同样带 confidence_tier。原则"允许 0 个 A 档可信 idea"不等于"必须返回 0 个 idea"——用户要的是分级方向清单，而非"要么完美要么空手"。需在 models.py 给 intervention/idea 加 confidence_tier 字段+ Alembic 迁移。

配合放松 Intervention 的 feasibility gate 误杀。当前用关键词子串匹配（" training"、"训练"、"benchmark"）判 FAIL，LLM顺口写"训练一个小分类器"就被一票否决。改为让 LLM 结构化输出"是否需要模型训练/训练规模"，或把硬 FAIL 降级为"标注风险的 B 档"。

### 第 2 档：补上游证据供给（3-5 天，见效快）

O5a 用 API embedding 启用全文 RAG。用OpenAI / Venus 的 embedding 接口替代本地 sentence_transformers，绕开 Windows PyTorch segfault，重新启用 `rag_retrieve` 与全文索引。这直接解决"全文供给 vs 全文需求"的结构性错配——Gap 挖掘准入门偏好的全文可定位证据终于有真实供给，Gap 从 B 档升到 A 档，同时 Idea 的 method_sketch 有全文 grounding，幻觉率大幅下降（参考 OpenScholar：全文段落检索使幻觉率接近 0，纯摘要推断 78-90%）。需改造 rag_service.py 的 embedding 后端为可插拔（本地 / API 双实现）。

O7 检索结果预过滤。在 `search_and_save_papers` 入库前，用 embedding 算 topic-paper 相似度，低于阈值（如 0.5）直接丢弃。复用 O5a 的 API embedding 即可，无需额外本地模型。噪声减少后，evidence 抽取和 Gap 挖掘的信噪比、以及评分区分度都会显著提升。

O6+ limitation 信号继续增强。在已有基础上，对 PDF 的 "Limitations" / "Threats to Validity" / "Future Work" / "Discussion" 章节做定向抽取（`extract_pdf_text_by_section` 已具备分章节能力），这些章节是 limitation 富矿，直接喂给 Gap 挖掘准入门的 `NO_LIMITATION_SIGNAL` 检查。

### 第 3 档：产出体验与前端（3-5 天）

前端 V2 适配。新增 Gap 视图（展示 target_setting / observed_problem / missing_capability / testable_hypothesis / falsification_condition / provenance_status 分档 / 审计状态）、Intervention 视图、Landscape Brief 独立视图（研究问题树、覆盖矩阵、论文角色分布、已知 limitation 清单、未覆盖区域、以及"为何没产出可信 idea + 建议下一步"的诚实解释）。当前这些中间产物要么用户看不到，要么挤在旧 Report 通道。这是让用户"即使没拿到 idea 也拿到有价值领域地图"的关键。后端 API 已有只读Gap 路由（`GET /tasks/{id}/gaps` 等），前端对接即可。

评分跨论文校准（O 补充）。评分时把同批次论文标题列表一起给 LLM 做相对比较，或在评分后做批内归一化/排名重标定，提升高优先级论文的区分度。

### 第 4 档：架构演进（按需，可延后）

PostgreSQL 迁移（docs/08 已有设计）：仅当需要多用户并发时再做，当前 SQLite + WAL 对单用户足够。文献地图（docs/12设计文档）：引文网络 + 语义聚类双层可视化，复用 RAG embedding，用户可见价值高，但依赖 O5a 先落地。这两项非当前瓶颈，不建议现在投入。

## 四、建议落地顺序

如果只做一件事：第 0 档配S2 key（10 分钟），立刻缓解限流，多道闸门通过率上升。

如果做两三天：第 0 档 + 第 1 档的 O2 定向补检索回环。这两者组合能把"大概率空手而归"直接变成"卡住时自动补检索重试，实在不行也至少交付分级方向 + 领域简报"，是解决"很难做"体感最直接的一击。

如果做一到两周：加上第 2 档的 O5a（API embedding 全文 RAG）+ O7（检索预过滤）+ 第 1 档的 O1（分级贯通）。这是根治——把 8% 的端到端通过率结构性提上来，同时守住"防幻觉/允许 0 个 A 档 idea"的底线。

如果做一个月：再加第 3 档前端 V2 适配，让 V2 的证据驱动价值真正对用户可见。

---

## 五、一句话总结

方向没错——V2 的证据驱动 + 对抗审计是对抗 LLM 幻觉的正解。当前痛点来自把防御性极强的长链做成了全严硬闸门串联，且上游（S2 限流 + Windows 无全文 + 无预过滤）供给不足、失败即终止无回环。解法不是退回 V1，而是：配 S2 key 补供给、失败即定向补检索回环、API embedding 启用全文、分级产出贯通全链、前端让中间产物可见，并永远至少交付一份领域态势简报。
